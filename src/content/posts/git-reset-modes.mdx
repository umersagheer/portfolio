## The one idea

{/* THE load-bearing sentence: `git reset` moves the current branch pointer to
    another commit. That's the whole verb. Soft/mixed/hard differ ONLY in what
    they do to the two things in front of the commit: the index and the working
    directory. Callback to flagship: "a branch is just a pointer" — this is that
    fact, weaponized. */}

## Three places your code lives

### --soft — move the pointer, keep everything staged

{/* Intent: pointer moves back; index + working dir untouched → the undone changes
    sit staged, ready to recommit. Use case: squashing several commits into one. */}

### --mixed (the default) — move the pointer, unstage

{/* Intent: pointer moves, index reset to match target, working dir untouched →
    changes still in your files but unstaged. Use case: restage differently. */}

### --hard — move the pointer, wipe everything

{/* Intent: pointer moves, index reset, working dir reset → uncommitted changes in
    TRACKED files are gone. The one destructive mode. Untracked files survive even
    --hard (worth stating explicitly — common misconception). */}

## "But I lost a commit"

{/* Intent: the reassurance beat. The commits you reset PAST aren't deleted — they're

    The ONLY unrecoverable thing is uncommitted work destroyed by --hard. */}
