## The one idea

{/* THE sentence: if the branch you're merging in is simply AHEAD of you (no new
    commits on your side), Git doesn't merge anything — it fast-forwards, sliding
    your branch pointer up the existing line. It only builds a real merge commit
    when both sides have moved and history has actually diverged. */}

## Fast-forward: no new object at all

{/* Intent: main hasn't moved, feature is ahead. There's a straight line for the
    pointer to slide along, so Git just overwrites main's hash with feature's hash.
    Zero new objects. The "merge" is a pointer update. Callback: branch = pointer. */}

## 3-way merge: the two-parent commit

{/* Intent: both main and feature moved → no straight line. Git finds the common
    ancestor (the "base", the 3rd point in "3-way"), combines the two snapshots, and
    writes ONE new commit whose special property is TWO parent lines. Only then does
    main's pointer move to it. This is the only object type in Git with two parents. */}

## Where conflicts come from

{/* Intent: short, optional. A conflict is just the 3-way merge finding that BOTH sides
    changed the same region relative to the common ancestor, so Git can't pick — it
    asks you. Ties conflicts back to the 3-way mechanic instead of treating them as
    a separate scary thing. */}
