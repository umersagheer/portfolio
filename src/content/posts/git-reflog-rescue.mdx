## The one idea

{/* THE sentence: Git records every move HEAD makes — every commit, checkout, reset,
    rebase — in a log (the reflog). Because commits are immutable and never really
    deleted, that log is a map back to any state HEAD was ever in. */}

## Why the commit is still there

{/* Intent: callback to the whole flagship. reset/rebase/detached-HEAD "lose" commits by
    making them UNREFERENCED, not by deleting them — the objects still sit in objects/.
    They stay until garbage collection, which has a grace window (~90 days reachable, ~30
    unreachable). So "5 minutes ago" is always recoverable. */}

## The rescue, in two commands

{/* Intent: `git reflog` → find the line/hash for the state you want back → `git branch
    <name> <hash>` (or reset --hard to it) → a pointer now references that commit again,
    it's reachable, it's yours. That's the entire recovery. Demystify it to two steps. */}

    snap onto it and pull it back into the reachable graph. The recovery-from-nothing moment.
    Build when writing. */}

## The one thing reflog can't save

{/* Intent: honesty beat. Reflog recovers COMMITTED work. Uncommitted changes destroyed by
    reset --hard were never objects in the first place → nothing to recover. The lesson:
    commit early; a commit is a save point the reflog can always find. Callback [[git-reset-modes]]. */}
